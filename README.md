# HPC 工作台

把实验室集群的 SSH + SLURM 命令行，包成一个能看、能点、能拖的桌面应用。

> Electron · React · TypeScript · ssh2 · xterm.js · 1064 条测试 · 14 篇设计文档

## 为什么做这个

我的日常是：`ssh` 上登录节点 → `cd` 到实验目录 → `squeue --me` 看有没有卡 → `sbatch` 交一批 →
一小时后 `scp` 把结果拉回来。一天重复十几次，在三个终端窗口之间切换，还经常记错作业号。

所以我想验证一个判断：**集群运维这类"命令很短、但心算很多"的活，做成图形界面到底值不值。**

这个项目就是答案。顺带把我踩过的坑全写进了 `docs/`——那些才是这个仓库里最值钱的部分。

## 界面一览

无边框窗口，左边一条 Dock 是七个页面；标题栏常驻三个数字（作业数 / 存储水位 / 点数余额）、
跳板机切换、通知铃铛和搜索框——`Ctrl K` 不只是搜，还能直接跳页面、跳作业。

| 页面 | 一句话 |
|---|---|
| **文件** | 左右双栏：本机 / 集群。拖拽传、右键菜单、批量选择；底部是传输队列 |
| **作业** | 队列与历史两栏。提交表单、日志跟随、取消；可选「按批次合并」 |
| **资源** | 机型卡片（库存 / 报价 / 卡位格子）+ 存储配额 + 点数余额 |
| **隧道** | 本地转发与反向隧道，含"端口被谁占了"的排查 |
| **终端** | 真 PTY 的 xterm，可以和图形界面同时用 |
| **设置** | 跳板机编辑、凭据、配置目录、主题、字体、测速、关窗行为 |
| **诊断** | 连接探针、诊断包导出 |

再加一层**命令记录**：所有远端命令（谁发的、耗时多久、退出码、输出）自动留痕，
出问题时不用凭记忆复述"我刚才敲了什么"。

## 它能做什么

**文件**
- 双栏拖拽、多选、复制、剪切、重命名、删除（走回收站）
- 传输队列：实时进度、限速、取消、失败原因
- **目录增量同步**：只传变了的文件，大文件可续传；语义是**只增不删**

**作业**
- 队列实时刷新、提交表单、日志跟随（`tail -f`）、取消
- 提交时按集群规则校验（`--gres` 必须带型号、每卡最多 4 核）
- **按批次合并**：一次实验 30 个 job 折成一行，结束时只发一条汇总通知
- 生命周期通知：开始 / 掉队 / 完成 / 失败，附节点、退出码、状态原因

**资源**
- 机型库存、配额水位、点数余额、按型号报价
- **卡位矩阵**：一张卡一个格子，一眼看出"现在能不能立刻跑"

**连接**
- 多跳板机切换（切换前会检查有没有传输 / 隧道在跑）
- **四段延迟探测**：把"连得慢"拆成 网络 / sshd 响应 / 认证 / 命令往返
- 主机指纹校验、首次向导、从 `~/.ssh/config` 导入

**其它**
- 正 / 反向隧道（让集群借本机代理出网）
- 三套主题、字体方案、诊断包导出

## 几个值得一提的实现

**1. 把"慢"拆开：四段延迟探测**

用户看到"连接要 1.2 秒"只会去查宽带，而实际原因往往是**登录节点在忙**——网络只花了 12ms，
剩下 1.1s 全耗在密钥交换和认证上。所以测速按 TCP → sshd 应答 → 认证 → `echo` 往返分成四段，
每段独立超时（5s / 15s / 5s，总预算 25s），并且**超时也要带数据回来**：
认证超时时报"网络 12ms 正常，卡在登录"，而不是一句"连接失败"。

难点是拿到"sshd 第一个字节"的时刻。ssh2 不暴露这个时机，而直接在 socket 上挂 `data` 监听会把字节吃掉、
握手直接失败。解法是做一个 `Duplex` 适配器：读方向由我们推、写方向转发回去，ssh2 只看到一条普通双工流。

**2. 目录增量同步：只增不删**

用 `mtime + size` 比对而不是 hash——远端算 hash 等于把几 GB 经 SSH 拉回本地，正是要省掉的那笔开销。
远端一条 `find -printf '%y\t%s\t%T@\t%P\0'` 拿全树，按 `\0` 切分（文件名可以有空格、制表符、甚至换行）。

三条铁律：**绝不删除目标端文件**、**目标更新时不覆盖**、**目录不参与覆盖**。
变更超过 40% 或 500 个文件时反而建议整包——每次 SFTP 都有一次往返，2000 个小文件比 tar 一个流慢一个数量级。

**3. 诊断包：脱敏是功能的一部分**

出问题时一键打包现场（版本、配置、命令记录、探测结果）。这个包是要发给别人的，所以脱敏分两层：
结构化配置走**白名单**（只输出认识的字段），自由文本走**黑名单扫描**（`password=` / `token=` / `sk-…` / `-pXXXX`）。

测试里有一条**泄露硬断言**：塞一个已知密码进去，生成包后全文搜索必须找不到。
以后谁往包里多加一个字段，这条测试会先炸。

**4. PTY 命令的"成功"判定**

交互式通道没有退出码，只能看输出。早期用"输出里有没有 Success"判断，结果是：
转账成功 → 挂到超时 → 判为失败 → 用户重转，**钱转两次**。

现在改成追加哨兵 `; printf '\n__HPC_DONE_<nonce>__:%s\n' "$?"`——**见到哨兵才算结束**，并用 `$?` 判成败。
这条教训在 `docs/04 §4.9`。

**5. 轮询分级，但托盘驻留是例外**

作业 20 秒、配额 / 点数 5 分钟；失败按 2× / 4× 退避、封顶 5 倍；窗口隐藏**完全停发**。
但"关窗收进托盘"之后窗口就是隐藏状态——如果还停发，作业跑完就没有通知了，正好和托盘的目的相反。
所以可见性条件是 `!document.hidden || trayResident`，由主进程下发。

测试不是为了覆盖率，是为了钉住那些**看起来对、实际会骗人**的边界。以下每条都来自真机实测，
记在 `docs/03`：

- `scontrol` 从不返回 `MIXED`——有作业就报 `ALLOCATED`，但上面仍可能空着卡
- `sacct` 里 `FAILED` 的作业，`exit_code` 可能仍是 `SUCCESS`
- `JobHeldUser` 是"你手动暂停"，不是排队；`reason=Priority` 是等优先级，不是缺资源
- `/tmp` 是节点本地盘，不共享
- `127.0.0.1` 是全体用户共享的（实测 643 个监听端口 / 143 个 uid）
- 每张卡最多跑 4 核，`--gres` 必须带型号

## 快速开始

需要 Node 18+（开发用 22）。

```bash
npm install
npm run dev
```

首次启动会走向导：填主机、端口、用户名、认证方式（私钥或密码）。
也可以把 `profiles.example.json` 复制成配置目录下的 `profiles.json` 再填。

```bash
npm run typecheck     # 类型检查（node + web）
npm test              # 1064 条用例
npm run build         # 只构建
npm run dist          # 打 Windows 安装包 → release/
```

认证信息存系统钥匙串（Windows DPAPI / macOS Keychain），**配置文件里不放密码**。

## 目录结构

```
src/
  main/       主进程：唯一碰网络的地方
    adapters/   解析集群 JSON → 领域对象（解析错了改这里）
    domain/     纯计算：库存、作业状态、配额（算错了改这里）
    transfer/   传输队列、tar 流、增量同步
    ssh/        连接池、会话、命令拼接、指纹校验
  preload/    IPC 白名单（渲染层没有 Node 权限）
  renderer/   React 界面
    components/  页面与通用组件
    lib/         纯前端逻辑（命令面板、选择、批次分组）
  shared/     主进程与界面共用的契约和纯函数
docs/         14 篇设计与验收文档
tests/        74 个测试文件
```

三条分层原则：**解析错 → `adapters/`；计算错 → `domain/`；卡顿 → `transfer/` 或界面。**
碰网络的逻辑绝不允许出现在 `renderer/`。

## 已知边界

- **只面向一个集群**：数据契约按我用的那套 `--json` 输出实测，换集群要重新探测
- **不做删除同步**：增量同步只增不删，这是刻意的——一次误操作能删掉实验数据
- **无代码签名**：Windows 首次运行会被 SmartScreen 拦一次
- **主题只有三套**：每套都要过对比度检查，加一套的成本比看上去高
