# HPC 工作台

把 SSH + SLURM 的命令行，包成一个能看、能点、能拖的 Windows 桌面应用。

**[↓ 下载安装包](https://github.com/6-Steve/hpc-workbench/releases/latest)**　
Windows 10 / 11 · x64 · 约 85 MB · 不需要管理员权限

---

## 装

1. 在 [Releases](https://github.com/6-Steve/hpc-workbench/releases/latest) 页下载最新的 `HPC-Workbench-*-setup.exe`
2. 双击运行。**没有做代码签名**，Windows SmartScreen 会拦一次：点「更多信息」→「仍要运行」
3. 装到当前用户目录（`%LOCALAPPDATA%\Programs`），不会弹 UAC

卸载走「设置 → 应用」，配置和凭据会留在原地，不会一起删掉。

## 第一次打开

三步向导：

| 步骤 | 填什么 |
|---|---|
| **配置放在哪** | 默认跟着系统用户走。也可以选「程序目录（便携）」——整个文件夹拷走就能换台机器用 |
| **连接信息** | 名称、主机地址、端口、用户名；认证方式选**私钥文件**或**密码** |
| **隧道端口** | 反向隧道默认 21056，被占会自动退到邻近空闲端口 |

密码存进 Windows 凭据管理器（DPAPI 加密），**不写进配置文件**。钥匙串不可用时会直接拒绝保存，
不会退回明文。

已经有 `~/.ssh/config` 的话，向导里可以一键导入，只认 `HostName` / `User` / `Port` / `IdentityFile`。

## 界面

无边框窗口，左边一条 Dock 是八个页面。标题栏常驻三个数字（作业数 / 存储水位 / 点数余额），
**点一下就能跳到对应页面**；右边是跳板机切换、通知铃铛和搜索框——`Ctrl K` 不只是搜，
还能直接跳页面、跳作业。

| 页面 | 做什么 |
|---|---|
| **文件** | 左右双栏：本机 / 集群。拖拽传、右键菜单、批量选择；底部是传输队列 |
| **作业** | 队列与历史两栏。提交表单、日志跟随、取消；可勾「按批次合并」 |
| **资源** | 机型卡片（库存 / 报价 / 卡位格子）+ 存储配额 |
| **点数** | 余额、消耗记录与赠送 |
| **隧道** | 本地转发与反向隧道，含"端口被谁占了"的排查 |
| **终端** | 真 PTY 的 xterm，可以和图形界面同时用 |
| **设置** | 跳板机编辑、凭据、配置目录、主题、字体、测速、关窗行为 |
| **诊断** | 连接探针、诊断包导出（发问题报告时用它） |

## 用之前值得知道的四件事

- **增量同步只增不删**：只传变了的文件，大文件可续传；对面更新的文件默认跳过，**多余的文件永不删除**
- **批次合并**：一次实验 30 个作业可以折成一条，全部结束时只弹**一条**汇总通知
- **托盘驻留**：可选「关窗不退出」。驻留期间轮询照常跑，作业跑完照样通知
- **命令记录**：所有远端命令自动留痕（命令、耗时、退出码、输出），出问题不用凭记忆复述

## 常见问题

**连不上 / 特别慢**
去「诊断」页点连接探针。它把耗时拆成四段——网络握手 / sshd / 认证 / 命令往返——
能区分"你的网慢"和"登录节点在忙"。四段里哪一段最长，问题就在哪。

**反向隧道说端口被占**
集群上的 `127.0.0.1` 是全体用户共享的，热门端口撞车很常见。隧道页会列出占用者的 uid，
点一下就能换到邻近的空闲端口，并给出三行 `export`——**不会去改你的 `~/.profile`**。
注意 tmux 里继承的是 tmux server 启动时的环境，改完要在新会话里才生效。

**关掉窗口程序还在跑**
这是「托盘驻留」，去设置里改。默认是只在有传输或隧道时才驻留。

**一台机器上的配置想搬到另一台**
向导里选「程序目录（便携）」，整个文件夹拷走即可。已经装好的可以在设置里改配置目录，
但**换目录要重启应用**。

## 已知限制

- **只面向一个集群**：所有数据靠解析 SLURM 的 `--json` 输出得来，换一套集群要重新适配解析层
- **没有代码签名**：首次运行会被 SmartScreen 拦一次
- **只有 Windows**：不做跨平台
- **不做删除同步**：这是刻意的——一次误操作能删掉实验数据

## 从源码跑

需要 Node 18+（开发用 22）。

```bash
npm install
npm run dev          # 开发模式
npm run typecheck    # 类型检查
npm test             # 单元测试
npm run dist         # 打 Windows 安装包 → release/
```

`npm run probe` 是连接探针，`npm run inspect` 用来查看某条命令解析出来的结构——两个都需要真集群。

架构上是 Electron 主进程 / 渲染进程分离：**碰网络的逻辑全在 `src/main/`**，渲染层没有 Node 权限，
只能调 `preload` 暴露的白名单方法。定位口诀：解析错找 `adapters/`，计算错找 `domain/`，
卡顿找 `transfer/` 或界面。

想接自己的集群，先看 `docs/03-数据契约与解析规范.md`——里面是每条命令的实际 JSON 长什么样、
哪些字段会骗人。产品层面的取舍在 `docs/01-产品设计方案.md`。

## 隐私

仓库里没有主机地址、用户名、密码、私钥、实验室标识、集群手册。
`.gitignore` 排除了本机配置、凭据文件、主机指纹与原始采集样本。
「诊断」页导出的诊断包同样走脱敏：配置走白名单，自由文本扫密码模式。
