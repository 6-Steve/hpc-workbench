# 内部接手说明与脱敏规则

> 从旧版 README 里保留下来的两块内容：**给下一个人（或下一次对话）的接手提示**，
> 以及**仓库里为什么没有真实集群信息**。对外版 README 见仓库根目录。

## 一、接手提示

新开一次对话时，直接粘这段：

```
我在继续开发 Windows 桌面应用「HPC 工作台」（Electron + React + TS，自用 + 作品集）。
请先读 README.md，再读 docs/04-开发交接说明.md；
动解析层之前读 docs/03-数据契约与解析规范.md；
想知道"还有哪些功能没验证"读 docs/13。

当前状态：v0.2.0，功能已成型（文件/作业/资源/隧道/终端/设置/诊断七大页），
1064 条测试全绿，已打出安装包。剩下的主要是人眼验收与打磨。

请严格遵循 docs 里已确定的决策，不要重新讨论技术选型（Electron vs Tauri、
要不要窗口管理器、要不要在集群装服务端——这三条都定过了）。
```

## 二、隐私与脱敏规则

仓库里**没有**真实集群信息。三类内容的处理方式：

| 内容 | 位置 | 是否提交 |
|---|---|---|
| 集群真实原始输出（节点名、用户名、文件系统名） | `internal/原始采集样本-*.md` | ❌ `.gitignore` 排除 |
| 脱敏后的解析规则与样本 | `docs/03-数据契约与解析规范.md`、`fixtures/` | ✅ 可公开 |
| 主机地址、端口、用户名、私钥路径 | `config/profiles.json` | ❌ `.gitignore` 排除 |
| 凭据（密文） | `config/credentials.json` | ❌ 即使解不开也不提交 |
| 主机指纹 | `config/known_hosts.json` | ❌ 本机状态 |
| 界面偏好（关窗策略等） | `config/ui.json` | ❌ 本机状态 |

**脱敏规则**（改 `docs/03` 或 `fixtures/` 时必须沿用）：

| 真实信息 | 占位值 | 说明 |
|---|---|---|
| 用户名 | `alice` | 不用 `user01`——`alice` 在注释里读起来才知道是"人名"，不会和字段名混 |
| 主机 IP | `192.0.2.x` | RFC 5737 文档保留段，一眼看出是示例 |
| 打码后的 IP | `192.0.*.*` | 保留前两段，和 `maskHost()` 的行为一致 |
| 登录节点名 | `login-01` | |
| 跳板机标签 | `hpc` / `hpc-02` | 自定义标签，不是主机名，可保留 |
| 节点名 | `nodeNN` | 原 `gpuNN` |
| 文件系统 | `gpfs01` | |
| 作业名 | `exp-b001` / `exp-a-001` | |
| 研究项目名 | `exp-project` | |
| 本机安装路径 | `install-dir` | |

**格式特征全部保留**（`N/A`、`(S:0-1)`、合并单元格、列宽截断）——
否则测试就失去意义：解析器要处理的是真实格式，不是好看的假数据。

### 不能改的一类：集群专有命令名

`scir-account` / `scir-watch` 在 `src/main/adapters/*.ts` 里是**导出常量**
（`USAGE_COMMAND`、`GPU_PRICE_COMMAND`），改了应用就跑不通。它们留在仓库里是有意的：
这是"这个工具面向哪个平台"的说明，不是凭据。真要彻底去掉，得把命令名提到
`profiles.json` 的配置里——那是另一个改动，别在脱敏时顺手做。

`internal/` 是只追加的证据存档，用于将来怀疑"解析规则脱离实际"时回查。
**不要提交，也不要在这里改规则**——改规则改 `docs/03`。

## 三、写代码时的同一套要求

- 源码里不允许出现主机地址、用户名、集群路径，一律走配置
- 诊断包导出同样要脱敏（`src/shared/diagnostic.ts`，有"泄露硬断言"测试守着）
- 日志保持纯 ASCII（Windows 控制台 GBK，中文会成乱码）
