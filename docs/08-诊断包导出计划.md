# 诊断包导出 · 详细实施计划（2026-11-16 已实施，待验收）

> 目标：出问题时点一下，得到一个 `hpc-diagnose-<时间戳>.tar.gz`，能直接发出去。
> **这个功能的全部风险都集中在"脱敏"，不在打包。**

## 1. 目标与非目标

**做**

- 诊断页一键生成诊断包，用户选保存位置
- 包里是"能复现问题的最小信息集"：环境、脱敏配置、命令记录、探测结果
- 单个采集项失败**不影响**整包产出
- 附一份 `README.txt`，说明每个文件是什么、哪些被脱敏了

**不做**

- 不上传、不自动发送、不收集使用统计（应用不做任何"回家"的动作）
- 不打包**终端 scrollback**、文件内容、私钥本体
- 不打包含密文（`credentials.json`）

## 2. 包内结构

```
hpc-diagnose-20261116-201233.tar.gz
├── README.txt                  # 这是什么、怎么回传、哪些字段被脱敏
├── manifest.json               # 生成时间、应用版本、平台、采集项成功/失败清单
├── app-info.json               # appInfo()：版本、electron/node/chrome、配置目录
├── config-dir.json             # configDirInfo()：当前用的是哪种目录（便携/自定义/环境变量）
├── profiles.redacted.json      # 脱敏后的 profiles.json（白名单字段）
├── known-hosts.redacted.json   # 只保留算法 + 指纹，host 键脱敏
├── trace/
│   ├── recent.json             # 最近 200 条：命令、退出码、耗时、预览（每条 ≤2KB）
│   └── full/                   # 最近 20 条的完整输出（每条 ≤16KB）
│       ├── 1781-1.json
│       └── …
└── notes/
    └── probe.txt               # 仅当用户勾选"顺便测一次连接"时才有
```

**体积上限**：`recent` 200×2KB ≈ 400KB，`full` 20×16KB ≈ 320KB，gzip 后通常 **< 300KB**。
超过 **5MB** 就停止追加 `full/`，并在 manifest 里写 `truncated: true`。

## 3. 脱敏规则（核心）

> 原则：**配置走白名单**（只输出已知字段，不做整文件替换），
> **自由文本走黑名单扫描**（命令和输出里可能出现任何东西）。

### 3.1 结构化字段

| 字段 | 处理 | 例 |
|---|---|---|
| `host`（IPv4） | 保留前两段 | `192.0.2.46` → `192.0.*.*` |
| `host`（IPv6） | 保留前两组 | `2001:da8:1:2::5` → `2001:da8:*` |
| `host`（域名） | 保留首尾各 2 字符 | `login.example.edu.cn` → `lo***.cn` |
| `username` | 首字符 + 长度 | `alice` → `a***e(5)` |
| `privateKeyPath` | 只留 `~/.ssh/<文件名>` | `C:\Users\alice\.ssh\id_rsa` → `~/.ssh/id_rsa` |
| 配置目录 / 日志路径 | 用户名段替换 | `C:\Users\alice\AppData\…` → `C:\Users\<user>\AppData\…` |
| `label` / `id` | **保留**（不敏感，且是理解现场的关键） | `hpc` / `hpc-02` |
| `port` / 认证方式 | **保留**（诊断需要） | `2223` / `key` |

### 3.2 自由文本（命令原文、stdout/stderr 预览）

命令记录是诊断的核心，**不能整体遮掉**，所以要扫内嵌的敏感值：

| 模式 | 替换 |
|---|---|
| `(password\|passwd\|passphrase\|token\|secret\|api[_-]?key)\s*[=:]\s*\S+` | 值替换成 `***` |
| `sk-[A-Za-z0-9_-]{8,}` | `sk-***` |
| `Bearer\s+\S+` | `Bearer ***` |
| `-p\S{6,}`（`mysql -p…` 这类） | `-p***` |

> **宁可多遮，不可漏遮**——这个包是要发出去的。

### 3.3 绝不进包

- `credentials.json`（含密文；没有诊断价值）
- 私钥文件本体、`authorized_keys`
- 终端 scrollback、任何文件内容
- 完整未脱敏的 `profiles.json`

### 4.2 打包方式

用 **`tar-stream` 的 `pack` + `zlib.createGzip()`**：

- `tar-stream` 已是生产依赖（`transfer/tar-download.ts` 用它的 `extract` 解远端 tar）
- **不新增依赖**；Windows 上也不需要装 `tar`
- 全程流式写盘，不在内存里拼整包

```ts
const pack = tarStream.pack()
const gzip = createGzip()
pack.pipe(gzip).pipe(createWriteStream(target))
pack.entry({ name: 'manifest.json' }, JSON.stringify(manifest, null, 2))
// …逐项追加，最后 pack.finalize()
```

### 4.3 采集的容错

每个 section 独立 `try/catch`，失败写进 `manifest.sections[].error`，**继续采下一项**：

```ts
for (const section of sections) {
  try { await section.collect(pack) ; manifest.ok.push(section.name) }
  catch (err) { manifest.failed.push({ name: section.name, error: String(err) }) }
}
```

> 诊断包最怕"因为某个数据取不到而整包生成不出来"——偏偏出问题时正是各项都半死不活的时候。

### 4.4 保存位置

`dialog.showSaveDialog`，`defaultPath = app.getPath('downloads')/hpc-diagnose-<时间戳>.tar.gz`。

**不写死到某个目录**：写进 `%APPDATA%` 之类的地方，用户下一步就得找它。
生成成功后卡片上直接显示完整路径 + 「打开所在文件夹」（`shell.showItemInFolder`）。

## 6. 测试

### 6.1 脱敏（表驱动）

| 用例 | 期望 |
|---|---|
| `192.0.2.46` | `192.0.*.*` |
| `login.example.edu.cn` | 只剩首尾（`lo***.cn`） |
| `alice` | 首字符 + 长度，中间打星 |
| `C:\Users\alice\.ssh\id_rsa` | `~/.ssh/id_rsa` |
| `~/.ssh/id_ed25519` | 原样（没有用户名可漏） |
| `export TOKEN=abcd1234` | 值变 `***` |
| `mysql -uroot -pMyPass123` | `-p***` |
| `Authorization: Bearer abc.def` | `Bearer ***` |

### 6.2 打包

- 用假 deps 生成 → 用 `tar-stream.extract` 读回 → 断言文件清单与 `manifest.json` 字段
- 某个 section 抛异常 → 包仍生成，`manifest.failed` 里有它
- 超过 5MB → `full/` 停止追加且 `truncated: true`

### 6.3 泄露硬断言（最重要）

构造一份**含已知密码**的假 vault + 含密码的命令记录，生成包后解压全量扫描：

```
expect(包含文).not.toContain('MyPass123')
expect(包含文).not.toContain('abcd1234')
```

这条断言的意义是防回归：以后谁在包里多加一个字段，测试会先炸。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 脱敏漏掉密码 | 配置走**白名单**（只输出已知字段），自由文本再走黑名单扫描；两层 |
| 单项采集失败导致整包失败 | 每项独立 try/catch，失败写进 manifest |
| 包太大发不出去 | 预览 2KB/条、完整输出 20 条、超 5MB 停止追加 |
| 用户不知道发了什么 | 包里附 `README.txt`；界面上把"包含/不含"直接写出来 |
| 命令原文里带集群内部信息 | 命令是诊断核心，保留；但主机/用户名已脱敏，且不含输出全文（只 20 条） |
