### 1.2 分层与边界

四条不能破的界线，破了就是返工：

| # | 界线 | 为什么 |
|---|---|---|
| 1 | **碰网络的代码不许出现在 `renderer/`** | 渲染层没有 Node 权限，也没有连接池、重试、指纹校验 |
| 2 | **渲染层只能调 `preload` 白名单里的方法** | IPC 表面越窄，出错时越容易定位。`ipc.ts` 是唯一的注册点 |
| 3 | **解析失败必须返回 `raw`，绝不静默给空** | 空数据看起来和"集群上真的没有作业"一模一样 |
| 4 | **加/改/删任何 `window.hpc` 方法，`PRELOAD_API_VERSION` 必须 +1** | preload 不热更新，漏了就是成片 `is not a function` |

`Adapter` 契约（新 Adapter 照此实现）：

```ts
parse(raw: string): { ok: true, data: T } | { ok: false, reason: string, raw: string }
```

**改代码前的五条自检**：

1. 这段逻辑碰网络了吗？碰了就该在 `main/`，不该在 `renderer/`
2. 解析失败时会静默返回空吗？**必须是明确的失败 + 原文**
3. 有新信息发 IPC 给 UI 吗？**合并成 100ms 一次**
4. 远程路径拼接用的是 `/` 吗？用的是 `shq()` 吗？
5. 引入了需要编译的原生模块吗？**没有例外，不要引**

定位口诀：**解析错 → `adapters/`；计算错 → `domain/`；卡顿 → `transfer/` 或 `renderer/`。**

## 2. 关键模块职责

### 2.1 连接层 `src/main/ssh/`

| 模块 | 职责 | 关键约束 |
|---|---|---|
| `pool.ts` | 按 profile 维护连接，复用、重连 | **一个 profile 只保持一个 TCP 连接**，所有操作共享。SSH 握手 3–5 次往返，30ms RTT 下就是 150ms 白等 |
| `session.ts` | 封装 exec / SFTP / shell / 转发 | 并发 exec 要有信号量，**默认 4–6**，不要超过服务端 `MaxSessions`（默认 10） |
| `capabilities.ts` | 探测 JSON 能力 | 结果缓存进 profile。**不能写死**，集群升级后要自动用上 |
| `errors.ts` | 错误归一 | 原始 stderr **必须保留并可在 UI 查看**，这是用户自救的唯一途径 |
| `shell.ts` | `shq()` 单引号转义 | **所有远端命令拼接的唯一出口**，不许手写引号 |
| `interactive.ts` | 交互式命令（带密码提示的） | 哨兵判定，见 §3.4 之外的另一条：PTY 退出码 ≠ 命令退出码 |

### 2.2 解析层 `src/main/adapters/`

这是全项目最脆的部分。**解析规则全部在 `docs/03`，踩过的具体陷阱见 §3.2。**

| 模块 | 数据源 | 输出模型 | 难度 |
|---|---|---|---|
| `node-detail.ts` | `scontrol show node --json` | `Node[]` | 中。**库存真值**。`gres` 仍是字符串、`state` 是数组 |
| `squeue.ts` | `squeue --me --json` | `Job[]` | 低，注意 `{set,infinite,number}` 解包 |
| `sacct.ts` | `sacct --json` | `JobHistory[]` | 低，默认格式会截断 |
| `scontrol-job.ts` | `scontrol show job <id> --json` | 输出文件路径 | 中。字段类型不统一，被清理时仍 exit 0 |
| `quota.ts` | `mmlsquota` | `{bytes, files} × {used, soft, hard, grace}` | 中。双维度 + 单位后缀 |
| `points.ts` | `scir-account -d` | `{total, used, avail}` | 最低，单行三浮点 |
| `gpu-price.ts` | `scir-watch -s` | `Map<(host,type), price>` | 中。Unicode 表格 + 合并单元格 |

> 四条 SLURM 命令的 `--json` 实测**全部可用**（尽管报 23.02.3）。
> 但别误读：`gres` / `tres` 在 JSON 里**仍是字符串**，GRES 正则与 `(S:...)` / `(IDX:...)` 的区分照样要写。

### 2.3 领域层 `src/main/domain/`

不碰网络，纯函数，最容易测试。

- `node-state.ts` / `job-state.ts` — 状态枚举映射（`mix` ↔ `MIXED` 是词形差异不是大小写）+ 排队原因的人话翻译
- `inventory.ts` — 库存管线：总卡数 − 已分配 − 阻断节点。**不要拿单价命令里的空闲数当准**
- `sbatch.ts` — 提交参数拼装。**必须锁型号**，不锁则点 A100 可能跑在 V100 上
- `reverse-port.ts` — 反向隧道端口选择：固定端口必须在 `ip_local_port_range`（32768–60999）之外
- `port-owner.ts` — 端口被谁占了：读 `/proc/net/tcp` 的 uid，判占用不能只看 LISTEN
- `points-transfer.ts` / `egress.ts` — 点数与出口 IP 的对照

### 2.4 传输层 `src/main/transfer/`

| 模块 | 职责 |
|---|---|
| `planner.ts` | 把"复制/同步一组路径"翻译成计划：算 N / 总大小 / 平均大小，选引擎，并给出理由 |
| `engine.ts` | 路由器：按 `docs/02` 的矩阵选 tar 还是 SFTP |
| `tar.ts` | 打包 → SSH channel → 远端 `tar -x`；解到 `dest.partial` 再改名 |
| `sftp.ts` | 单流上下行：`fastPut`/`fastGet` + `.part` 改名 + 大小核对 |
| `sync.ts` | 增量同步的树遍历与差异比对（`mtime + size`，不用 hash） |
| `queue.ts` | 并发、指数退避重试、**按目标路径加锁**、冲突策略 |
| `progress.ts` | 按 100ms 合并进度再发 IPC |

两条硬规则：

- **远程 → 远程的移动必须在服务端 `mv` / `cp`**，不走传输引擎。这是同类工具最常见的错误
- **同步只增不删**：目标更新则跳过，多余文件永不删除。`onConflict` 在同步模式下必须固定 `overwrite`，
  否则队列层的默认值 `skip` 会把每一个"更新"悄悄跳过

### 2.5 渲染层 `src/renderer/src/`

- `components/` — 八页里七页各占一个文件：`FileView` / `JobsView` / `ResourcesView` /
  `PointsView` / `TunnelsView` / `TerminalView` / `SettingsView`；诊断页仍在 `App.tsx` 内。
  通用件（`PageShell` / `PageHeader` / `Field` / `Mono` / `Hint` / `EmptyState` / `StatusDot`）在 `ui.tsx`
- `lib/` — 不依赖 React 的逻辑：`command-palette`（打分排序）、`selection`（多选）、
  `job-groups`（批次）、`use-poll`（分级轮询）、`swr-cache`、`theme` / `font-theme`
- 页面骨架统一走 `PageShell` / `PageHeader`；例外是 `TerminalView` / `FileView`（满屏 `flex-col`）
- **样式只用 `tailwind.config.js` 注册过的语义 token**。写死数值或写错类名都会静默失效，见 §3.3 E29

## 3. 已知问题与坑

### 3.1 平台限制（无法绕过，只能适配）

| # | 问题 | 应对 |
|---|---|---|
| P1 | 没有 API，全靠解析 CLI 文本 | Adapter 隔离 + 失败保留原文 |
| P2 | ~~`sinfo` / `scontrol` 在 23.02 无 JSON~~ → **实测四条命令都有 JSON** | 已改用 JSON；固定格式解析保留为降级路径。教训：能力由构建决定，不由版本号决定 |
| P3 | 计算节点大多禁 SSH | 终端开在**登录节点**上；要在计算节点跑命令必须 `srun` 申请，不能直连 |
| P4 | 内网穿透被禁 | 所有访问走 SSH 隧道 |
| P5 | 无 root | 客户端不能装系统级依赖 |
| P6 | 跳板机禁大负载 | 轮询必须分级 + 退避（作业 20s / 配额 5min，失败封顶 5 倍） |

### 3.2 解析陷阱（会写出「能跑但结果错」的代码）

| # | 陷阱 | 后果 | 现状 |
|---|---|---|---|
| D1 | `sinfo` 的 `mix` vs `scontrol` 的 `MIXED` | 过滤失效 → 商店全空，且不报错 | ⚠️ 仍在，且 JSON 里 `state` 变成**数组** |
| D9 | `scontrol` **从不返回 `MIXED`**，有作业就报 `ALLOCATED` | 按 {idle, mix} 过滤 → 16 台只剩 1 台可售 | ⚠️ 实测踩到。改用"阻断/有货"两个概念 |
| D2 | `scontrol` 值内含空格（`OS=Linux 5.15...`） | `split` 崩；`[^=]*` 会在 `CfgTRES=` 处截断 | ✅ JSON 消除 |
| D3 | GRES 含 socket 后缀 `(S:0-1)` | 误当数量 | ⚠️ 仍在，`gres` 还是字符串；`gres_used` 用 `(IDX:...)` |
| D4 | 单节点多机型 | 只按 host 合并会串味 | ⚠️ 仍在，库存要按型号分别算 |
| D5 | `drain` 节点有大量空闲资源 | 当库存卖出去，作业永远排队 | ⚠️ 仍在，`["IDLE","DRAIN"]` 更容易踩 |
| D6 | `sacct` 默认格式三处截断 | GPU 数直接丢失 | ✅ JSON 消除 |
| D7 | `scir-watch` 合并单元格 | 续行机型为空，需 carry-forward | ⚠️ 仍在（表格命令，无 JSON） |
| D8 | `FREE_MEM` / `CPU_LOAD` 可能为 `N/A` | 数值解析抛异常 | ✅ 变成 `{set:false}`，但**别直接 `Number()`** |

**JSON 独有**：`{set,infinite,number}` 解包、`state` 多值数组、`gres` 与 `tres` 型号顺序不一致、
`tres_used` 内存单位与 `tres` 不同。详见 `docs/03`。

**时间戳**：返回的时间串**不带时区**，不要 `new Date()` 按本机时区解析。

### 3.3 工程陷阱

| # | 陷阱 | 应对 |
|---|---|---|
| E1 | 进度按数据包发 IPC | 每秒数百条消息，UI 卡死 → **按 100ms 合并** |
| E2 | tar 管道不处理背压 | 读进内存 OOM → 必须 `stream.pipeline` |
| E3 | 只检查本地 tar 退出码 | 远程解压失败但本地成功 → **静默丢数据** |
| E4 | 取消时只 kill 本地进程 | 远程 tar 变孤儿继续写盘 → 记录远端 PID |
| E5 | 并发超过 `MaxSessions` | channel open failure |
| E6 | 续传不校验三元组 | 续的是旧文件 → 拼接垃圾 |
| E7 | 远程路径混入 `\` | GPFS 上出现名为 `a\b` 的文件 |
| E8 | 文件名拼进 shell | 命令注入（SFTP/tar 安全，但建目录、改权限容易手滑） |
| E9 | 引入原生模块 | node-gyp + MSVC 编译失败。keytar 因此被否 |
| E10 | Electron 32+ 用 `File.path` | 返回 `undefined` 且不报错，表现为"拖进去没反应" |
| E11 | **SSH channel 只写不读** | 数据全进本地缓冲、**一个字节都发不出去**。必须 `stream.resume()` 把可读侧拉起来 |
| E12 | **拿 SSH channel 当 `pipeline` 的终点** | `pipeline` 等可读侧结束，可读侧等远端退出，远端等我们的 EOF → 死锁。改用 `.pipe()` 链 |
| E13 | **tar 下载不等 `extract` 的 `finish`** | channel 关闭 ≠ 解包完成，会丢最后几个文件 |
| E14 | **tar 下载没剥顶层目录名** | `tar -cf - -C <parent> <base>` 的 entry 带 `<base>/` 前缀，解开会多套一层 |
| E15 | **`pack.entry()` 不 await 回调就写下一条** | pack 严格串行。**先 pipe 到下游**再写，否则回调永远不来 |
| E16 | **假集群的 tar 流不写结束块** | tar 靠结尾两个 512 字节全零块判定结束，缺了只解出第一个文件 |
| E17 | **没堵 Chromium 的默认拖放导航** | 文件拖到非投放区，整个应用变成显示那个文件。要在 `dragover`/`drop` 上 `preventDefault` |
| E18 | **`dragover` 不 `preventDefault` 就不会有 `drop`** | 想拒绝某区域就**故意不** preventDefault——正好用来做"本机栏不接受外部文件" |
| E19 | **`path.dirname('C:\\')` 返回 `'C:/'`** | Windows 上会规范化分隔符，拿它和原串 `===` 永远不等。判盘符根要用正则 |
| E20 | **改 `src/preload/index.ts` 不会热更新** | 渲染层拿到新代码、窗口里跑的还是旧 preload → 成片 `is not a function`。**不是 bug，是没重启** |
| E21 | **`src/preload/index.d.ts` 在 node 侧 tsconfig 里看不见** | 和 `index.ts` 同名，TS 当成后者的声明输出而跳过，列进 `include` 也没用 |
| E22 | **`scontrol show job --json` 字段类型不统一** | `job_id` 是数字、时间是裸 epoch 秒、其余是 `{set,...}` 包装。作业被清理时**仍 exit 0**，只是 `jobs: []` + warning |
| E23 | **`--gres=gpu:N` 不带型号会被扩展拒绝** | 必须写 `--gres=gpu:a100-pcie-40gb:1`。`--test-only` 能拦这个，但拦不住配比 |
| E24 | **`tail -f` 不能走 exec 的信号量** | 它永不结束，占一个槽就是永久少一个。另外**必须用 `StringDecoder`**：汉字 3 字节会被 chunk 劈开 |
| E25 | **`Unable to bind to 127.0.0.1:55555` 不含原因** | 这句是 ssh2 自己拼的字符串，协议里没有携带原因的字段。`127.0.0.1` 在登录节点上是**全体用户共享的网卡** |
| E26 | **观测代码会反过来搞坏被观测的东西** | `TraceStore.push` / 每个订阅者 / `emitTrace` 三处都要 try/catch；记录必须**有界** |
| E27 | **"spawn 不到就 return"的测试等于没测** | 沙箱里 `spawnSync('bash')` 直接 EBUSY，那条用例一直是"绿的空壳"。改成检查真正会出错的结构特征 |
| E28 | **临时端口段里的端口会被"路人"抓走，而且没有 LISTEN** | 别人的客户端可能把源端口显式绑到你的端口上。**固定端口应选 32768 以下**，退端口要试多个候选 |
| E29 | **Tailwind 对未注册的 token 静默无输出** | `rounded-card` / `shadow-panel` 写错，构建、tsc、测试全过，只是样式没生效。要有守卫拿名字去配置里对 |
| E30 | **类名不是类型** | 同上，泛化版：i18n key、环境变量名，凡"配置里定义、代码里按名字引用"的都要守卫 |

### 3.4 六个自己造出来的回归

这份记录里最值钱的部分。**没有一个是靠读代码发现的**——全是实测或算数算出来的。

| # | 症状 | 真因 | 教训 |
|---|---|---|---|
| 1 | 状态色对比度不达标 | 色板按"背景色"直觉选了 500/600 档，但这批颜色有 172 处是当**正文色**用的，衬 tint 底只有 3.5–4.4:1 | 颜色收敛不能只看"统不统一"，**要算 WCAG**。全绿的测试不会告诉你字看不清 |
| 2 | 14 处状态灯没有背景色 | 批量正则把 `bg-state-ok/60` 改成了 `bg-state-ok/[0.06]0`——多一个 `0`，类名不存在，**一行 CSS 都不生成**。编译、tsc、631 条测试全过 | 批量改类名后**必须去构建产物 CSS 里确认规则真的生成了** |
| 3 | 命令面板搜不到上周的作业 | 截断写在排序之前：`history.slice(0, 200)` 取的是"最近 200 条"，不是"最相关的 200 条" | 任何 `slice` 都要问"我砍掉的是什么"。顺序由数据源决定就等于偷偷改语义 |
| 4 | 传 187 MB 时速度 678 KB/s、总进度 0% | `snapshot()` 聚合时漏了 `running` 状态的 `doneBytes` | **组装正确 ≠ 聚合正确**。进度类功能必须在"中途"断言，`enqueue → whenIdle → snapshot` 的测试永远看不到 `running` |
| 5 | 「取消」之后文件又冒回来 | `abort()` 只是把 Promise 变灰，异步操作还在写。三层试错：① `step` 里 throw 冒穿 ssh2 回调栈、整条会话挂掉；② 直接 reject 让外层 unlink → 删完又冒回来；③ 正解：`abort()` 只置位，settle 交给 `fastPut/fastGet` 的 callback，那时句柄已关 | **「请求停止」≠「确认已停止」** |
| 6 | 标题栏下拉被 Dock 压住 | `TitleBar` 上有 `backdrop-blur`，创建了**层叠上下文**，栏内 z-index 只在栏内排序，整体永远低于 Dock。改 `z-[9999]` 也没用 | 毛玻璃/滤镜/transform/opacity<1 都会创建层叠上下文。**"看起来在最上层"取决于层叠上下文，不是 z-index** |

第 6 条的续集：改用 `createPortal` 到 body + `fixed` 之后，卡片圆角又不对——因为写的是 `rounded-card`
和 `shadow-panel`，配置里**根本没有这两个名字**（只有 `control`/`surface` 和 `card`/`pop`）。
这就是 E29 的来源。另外 portal 浮层的**宽度必须写成常量**，首帧 `getBoundingClientRect()` 是 0 宽。
