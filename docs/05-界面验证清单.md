## A. 状态色"整块消失"（回归验证 · ✅ 已通过）

**这一条是回归验证，当初要求 GUI 起来后第一件事就看它。**

### 为什么必须看

2026-11 的批量改类名脚本把 14 处 `bg-state-*` 改成了 `bg-state-ok/[0.06]0`
这种**不存在的类名**，Tailwind 于是不生成任何 CSS，那 14 个元素变成没有颜色的空壳。
编译、两个 tsc、631 条测试、build **全部通过**，只有肉眼能发现。

已经改回来了，并且补了守卫测试（`没有拼错的类名残骸`）+ 产物 CSS 级确认
（四个类都真的生成了 `background-color`）。但**"CSS 生成了"不等于"元素上看得见"**——
中间还隔着元素尺寸、层级、是否被 `overflow` 裁掉，这些只能靠眼睛。

### 怎么验（5 分钟）

完全重启应用（关窗口，`npm run dev`），然后依次看这 6 处：

| # | 去哪儿 | 看什么 | 通过标准 | 没通过说明什么 |
|---|---|---|---|---|
| 1 | **终端页** → 标题右侧 | 「已连接」左边的**小圆点** | 有一个实心绿点 | 只有文字、左边空着 → 回归了 |
| 2 | **资源页** → 往下找配额卡 | 「空间」「文件数」**两条进度条** | 条内有颜色（绿/黄/红） | 只有灰底空槽 → 回归了 |
| 3 | **标题栏铃铛** → 点开通知中心 | 每条通知左边的**小圆点** | 有颜色（绿/红/黄/蓝按类型） | 点看不到 → 回归了 |
| 4 | 同上，让某条通知带**未读数** | 铃铛右上角的**红色数字徽标** | 红底 + 白字 | 数字直接飘在白板上 → 回归了 |
| 5 | **传输文件**时看底部传输条 | 蓝色**进度条** | 真的在增长且是蓝色 | 只有灰色轨道 → 回归了 |

加载提示旁边应该有个**跳动的蓝点**。

## 1. 列表不是空白

> 先把本机栏展开：顶部工具栏点一下「本机栏」。默认是收起的。

**做什么**：在左侧「本机」栏里逐级点进去 —— `AppData` → `Local` → `Temp` → `hpc-bench-list`。

**通过**：看到 4803 个条目，3 个目录（checkpoints / dataset / logs）排在最前，
名称 / 大小 / 修改时间三列对齐。

> 基线：主进程列出这 4803 条实测约 **105 ms**。超过一两秒说明本地 stat 出了问题。

**不通过**：
- 一片空白 → `ResizeObserver` 没生效，视口高度一直是 0，组件按设计不渲染任何行。
- 只有 3 个目录、文件没出来 → 列表数据本身有问题，不是滚动的问题。

## 2. 真的只渲染了少数行（核心检查）

按 **F12** 打开开发者工具，切到 **Console**，粘贴：

```js
const s = document.querySelectorAll('.overflow-y-auto')[0]
console.log('渲染行数:', s.querySelectorAll(':scope > div > div > div').length)
console.log('总高度:', s.scrollHeight)
console.log('视口高度:', s.clientHeight)
```

**通过**：
- 渲染行数在 **30–50** 之间（视口高度 ÷ 28 + overscan 的余量）
- 总高度约 **134500**（4803 × 28）
- 视口高度几百 px

**不通过**：如果渲染行数是 **4803**，说明虚拟滚动完全没生效，所有行都铺成了真正的 DOM 节点。
这正是这套组件要避免的情况。

滚动几下再重新跑一次上面的命令，**渲染行数应该维持在几十**，不随滚动位置增长。

> 你可以自己对比一下量级：4600 多个 DOM 节点 vs 40 个。
> 前者滚动时浏览器要重排几千个元素，后者只需要换掉几十个。

## 3. 行高与内容吻合

Console 里继续：

```js
s.querySelector(':scope > div > div > div').getBoundingClientRect().height
```

**通过**：输出 **28**，且肉眼看每一行文字都在行内垂直居中，不贴边、不截断、行与行之间没有缝隙。

**不通过**：
- 数字不是 28 → `FilePane.tsx` 的 `ROW_HEIGHT` 和实际样式不同步了。
- 文字被截掉上半或下半 → 行太矮，把 `ROW_HEIGHT` 调大（比如 30）。
- 行之间有明显缝隙或粘连 → 行太高或太矮，同样调这个常量。

> 调整时要记住：`ROW_HEIGHT` 是虚拟滚动算位置的唯一依据，
> 改了必须和行内样式（padding / 字号 / line-height）保持一致。

### 7.1 多选与选中态（2026-11-05 新增）

| # | 怎么做 | 期望 |
|---|---|---|
| S1 | 单击一个文件 | 整行变**深一档的蓝底 + 左侧一条 2px 蓝色竖条**，一眼能看出是哪一行 |

| M6 | 远程栏重复 M1~M4 | 行为一致。远程移动走 SFTP 的 rename，同一文件系统内是原子的 |
| M7 | 批量移动里有一个文件被占用 | 报「移走了 2 项，但…」，**没搬走那个仍保持选中** |

M3 是安全底线：`fs.rename` 和 SFTP 的 `RENAME` 都**默认覆盖**同名文件，
不先 stat 就是静默吃掉数据（集群上没有回收站，覆盖了就真没了）。

### 刷新（外部改动后能看到变化）

远端目录有 8 秒缓存（来回切目录才不卡），所以外部改动不会自动出现。验证：

| 做什么 | 期望 |
|---|---|
| 在应用里删一个远端文件 | 列表**立刻**消失（写操作会主动清缓存，不该等） |
| 用别的终端在远端 `touch 新文件.txt` | 列表没变（正常，缓存） |
| 点刷新按钮（或 `F5`） | 新文件出现 |
| 在回收站还原一个本地删掉的文件 | 点刷新按钮后能看到它回来 |
| 点刷新时看按钮 | 图标会转一下，表头下方出现蓝色脉冲条 |
| 双击一个 400+ 项的远端目录 | 切换过程中旧列表不闪白，顶部有脉冲条 |

### 删除的安全边界（这几条必须拦住）

在集群栏（右侧）试：

| 试什么 | 期望 |
|---|---|
| 删除家目录本身 | 被拒绝，提示「不能删除家目录本身」 |
| 删除 `/home` 这类一级目录 | 被拒绝 |
| 删除普通文件 / 自己的目录 | 正常删除 |

> 这些是主进程 `assertSafeRemotePath` 拦的，不是界面拦的。
> 即使界面出 bug 传了错参数，也删不掉家目录。

### 如果本地删除报「回收站可能不可用」

`shell.trashItem` 在 U 盘、网络盘、或系统禁用回收站时会失败。
这时确认框里会多出一个「我确认，永久删除」按钮，走的是 `fs.rm`，**不进回收站**。

点之前想清楚：这一步删完找不回来。

## 反向隧道（集群 → 本机，2026-11-04）

用途：让集群上的程序借你本机的网络出去（比如让 codex / 实验脚本 用本机 Clash 代理）。
对应原来手敲的 `ssh -R 127.0.0.1:21056:127.0.0.1:7897 hpc`（默认端口已从 55555 改成 21056）。

**这条功能有一个隐性约定：监听端口必须等于集群上 `~/.profile` 里 `http_proxy` 的端口。**
对不上的话隧道开着也没人用，而且界面上看着一切正常——所以要重点验这一条。

| 项目 | 怎么验 | 期望 |
|---|---|---|
| 方向切换 | 隧道页顶部两个按钮 | 「本机 → 集群」和「集群 → 本机」能切，下面的表单跟着换 |
| 默认值 | 切到「集群 → 本机」 | 监听端口默认 **21056**，本机目标默认 **127.0.0.1:7897** |
| 读到集群的 http_proxy | 同上，等一秒 | 表单下方显示「集群上 ~/.profile 里的 http_proxy：127.0.0.1:xxxx」，右边有「与监听端口一致 / 不一致」标记 |
| 不一致时的提醒 | 把监听端口改成和 http_proxy 不同的数字 | 出现黄条，说明"集群上的程序只连 xxxx，隧道开着也没人用"，并给出三行 `export` + 「复制这三行」 |
| 能开起来 | 端口和 http_proxy 一致时点「开反向隧道」 | 绿字「已开：集群 127.0.0.1:21056 → 本机 127.0.0.1:7897」，**没有**黄条 |
| 端口被占 → 自动退端口 | 故意填一个别人正在用的端口（先在集群上 `ss -ltn` 找一个） | 不报错，而是**开在邻近的空闲端口上**；出现黄框：`xxxx 被占了（账号 xxx 的进程），这次改用了 yyyy（一次性端口）`，并给出对应的三行 `export` |
| 退端口的提示要能直接用 | 复制那三行，粘到集群终端里 `printf '%s\n' "$http_proxy"` | 显示的就是新端口 |
| 附近全占时 | （难以构造，可用单测覆盖） | 报「集群侧端口绑不上」+ 点名占用者，不假装成功 |
| 列表里有标记 | 看「进行中」 | 有紫色「集群→本机」标签，写的是 `集群 127.0.0.1:<实际端口> → 本机 …`，**没有**「打开浏览器」按钮 |
| 集群上真能用 | 在集群终端里 `curl -x http://127.0.0.1:21056 https://api.ipify.org` | 返回**你本机 Clash 的出口 IP**，不能是别人的（拿本机 `curl -x http://127.0.0.1:7897 https://api.ipify.org` 对比） |
| 本机代理没开 | 把 Clash 关掉，再从集群那边发起请求 | 请求失败（干净断开）；应用里显示「最近一次连接失败：连不上本机 127.0.0.1:7897 …」 |
| 关闭释放端口 | 点「关闭」，再从集群 `curl 127.0.0.1:21056` | 连不上 |
| 退出应用释放 | 开着反向隧道退出应用，重新打开 | 能再开同一个端口（说明退出时释放了） |
| 两个方向能共存 | 同时开一条 `本机→集群` 和一条 `集群→本机` | 列表里两条都在，各自标签清楚，互不影响 |

## 命令台 / 命令记录（2026-11-04 新增）

入口有两个：标题栏右侧「命令」按钮（`>_` 图标）、**Ctrl + 反引号** 快捷键。命令面板里搜「命令记录」也能开。

| 项目 | 怎么验 | 期望 |
|---|---|---|
| 默认收起 | 刚启动时 | 底部没有抽屉；标题栏「命令」按钮是灰的 |
| 打开后立刻有内容 | 点「命令」 | 抽屉从底部弹出，**已经有历史记录**（不是只从现在开始记）。先切到「作业」页再打开，能看到 `squeue --me --json` |
| 命令是真的 | 对照「作业」页 | 抽屉里出现 `squeue --me --json`，耗时几十到几百毫秒，退出码 0 |
| 输出能看 | 点任意一行展开 | 显示完整命令 + stdout；`squeue` 那条点「看完整输出」能拿到完整 JSON（列表里只给前 4000 字，会提示"共 N 字"） |
| 失败要显眼 | 在「提交作业」里填一个必然失败的参数（如 `--gres=gpu:9` 且型号不匹配）提交 | 抽屉里出现红底一行，退出码非 0，展开能看到 stderr 原文 |
| 未执行也算一类 | 断开网络后点某个刷新按钮 | 出现红底「未执行」标签，展开写着"命令没有跑成：…"，与"远端返回非 0"区分得开 |
| 只读，不能执行 | 通读抽屉 | 没有输入框能敲命令。想敲命令去「终端」页 |
| 过滤 | 在过滤框输入 `scir` | 只剩含 scir 的记录，右侧显示「n/总数」 |
| 只看失败 | 点「只看失败」 | 只剩失败项；再点恢复 |
| 跟随 / 暂停 | 停在抽屉里不动，等 20 秒轮询 | 自动贴着底部滚动；用鼠标往上翻一下，「跟随中」变「已暂停」，不再被顶走，滚回底部又自动恢复 |
| 清空 | 点「清空」 | 列表立刻空，显示空状态说明；主进程那边也清了（重新打开抽屉不会"复活"） |
| 收起后仍继续记 | 收起抽屉，去点几个页面，再打开 | 期间发生的命令都在（抽屉收起不影响录制） |
| 有上限 | 让它跑很久 | 最多 200 条，最旧的被顶掉，不影响其它功能 |
| 重开记住状态 | 开着抽屉退出应用，再启动 | 抽屉仍是开的 |
| 不抢快捷键 | 在「终端」页按 **Ctrl + 反引号** | 由终端自己处理（应用不抢） |

**边界（不是 bug）**：跟随日志、交互式终端、端口转发、上传下载**不会**出现在这里——它们不是"一条命令一个结果"的形状，SFTP 传输压根不走 exec。文件操作请对着「传输」列表看。

## 反向隧道自检「测一下能不能用」（2026-11-04 新增）

入口：隧道页「进行中」列表里，每条 `集群→本机` 的隧道右边。

它做的事：在集群上经这条隧道 `curl` 一次 `api.ipify.org`，同时在本机经 Clash 也取一次，
**比对两个出口 IP**。一致才算真的通了——只看"端口在监听"会被别人的服务骗过去。

| 项目 | 怎么验 | 期望 |
|---|---|---|
| 正常情况 | 开着隧道，点「测一下能不能用」 | 2–5 秒后出现绿字：`可用 · 出口 x.x.x.x，和你本机一致` |
| 不能只看端口 | 通读结果 | 必须出现**两个** IP 的比对结论，只说"通了"不算 |
| Clash 关掉 | 退出 Clash，再点 | 红字：两边都不通，先确认 Clash 开着 |
| 隧道已关 | 关掉隧道后点（列表里已消失，用旧实验：开着测一次，关掉再开一条别的） | 结论按隧道 id 存，关掉的那条不会残留上一次的绿字 |
| 本机端口不对 | 把隧道目标端口改成 7898（没人听）再测 | 黄字：集群侧通了但本机没响应，没法比对 |
| 忙时不卡界面 | 点一下立刻切到别的页签再回来 | 按钮显示「测试中…」，不阻塞其它操作 |

## 「偶尔撞一回」的处置（写给人看的）

默认端口偶发绑不上时，**不要改配置文件**，按这个走：

1. 点「开反向隧道」。它会自动换到邻近的空闲端口，界面上出现黄框，写明被谁占着、这次用的是哪个端口。
2. 点黄框里的「复制这三行」。
3. 粘到**要跑实验的那个**窗口，回车。只影响这个窗口。
4. 重启那个实验进程（老进程读的是旧值）。
5. 回来点「测一下能不能用」，出口 IP 对得上就收工。

一周撞两次以上才值得改成固定端口；改的时候三处一起改（`.profile`、`tmux set-environment -g`、
应用里的监听端口）。
