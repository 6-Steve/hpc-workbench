# 资源页卡位矩阵（2026-11-16 已实施，待验收）

> 目标：把「这台机器还剩几张卡」从**一个数字**变成**几个格子**。
> 一眼看出"现在能不能立刻跑"，不用逐行读 `卡5 核48/64 62G`。

## 1. 目标与非目标

**做**

- 每个 GPU 型号卡片内，节点明细行右侧画一排格子：一张卡一个格
- 卡片头部加一条**占用比例条**（纯视觉，不重复已有的大数字）
- 点格子 = 看这台机器上谁在用（复用现有 `NodeJobsDialog`）
- 格子状态严格由 `blocked + 每型 free` 推导，**不看状态名**

**不做**

- 不做独立页面/新页签（现在信息密度已经够，多一个入口反而分散）
- 不做动画、闪烁、"新空闲提醒"（集群状态 20 秒才刷新一次，闪烁只会骗人）
- 不做拖拽/点选下单（下单入口已经在卡片头）
- 不显示 blocked 机器（`inventory.usableNodes` 本来就不含它们，保持现状）

## 2. 现状

`ResourcesView` → `GpuTypeCard` 展开后，每个节点一行：

```
gpu10   卡5   核48/64   62G           谁在用
gpu11   卡0   核64/64   —     核满    谁在用
```

数字都对，但**"5 张是哪些、还剩几张"要靠减法**。16 台机器 × 8 卡 = 128 个数的减法。

## 3. 放哪儿

| 位置 | 内容 | 理由 |
|---|---|---|
| 卡片头部 | 6px 高的比例条：`空闲 12 / 32` | 回答"整体还有多少"，和已有的大数字并列不冲突 |
| 节点行 | `■■■■□ □□` 一排格子 | 回答"哪台有货、有几张" |
| 格子 hover | `gpu10 · A100 · 第 3 号卡空闲` | 精确到第几张 |

**不新开一块**：卡片已经把"型号"这一维分好了，矩阵放进去天然免掉一维。

## 4. 数据：一个纯函数决定一切

新增 `src/shared/gpu-slots.ts`：

```ts
export type SlotState = 'free' | 'used' | 'blocked'

export interface SlotNode {
  name: string
  blocked: boolean
  gpus: Array<{ type: string; count: number }>
  gpusUsed: Array<{ type: string; count: number }>
}

export function slotsOf(node: SlotNode, type: string): SlotState[]
export function slotSummary(nodes: SlotNode[], type: string): { total: number; free: number }
```

用**结构类型**而不是 import `NodeInfo`：`NodeInfo` 是全局声明，共享层不该依赖主进程的适配器模块。

### 三条必须照抄的规则（都来自 `docs/03` 实测）

| 规则 | 为什么 | 写错的后果 |
|---|---|---|
| **`blocked` 的机器整台标灰**，不管它还剩几张卡 | drain / down 的机器调度器不派活 | 显示 8 张空闲，用户点了却发现提交不上去 |
| **有作业 ≠ 没卡**（`ALLOCATED` 可能还有空卡） | `scontrol` 从不返回 `MIXED` | 用 `state === 'idle'` 过滤会把 16 台砍成 1 台 |
| **按型号分别算** | 一台机器可能 A100×4 + V100×4 | 先合总数再摊，会出现"V100 显示 8 张空闲" |

补充两条：

- `used > total`（节点与作业统计不同步）→ free 取 `max(0, total-used)`，并把格子全标占用；**不要**画出负数个格子
- 某型号 `count === 0` → 不画格子，保留原来的数字（不要让空行占位）

## 5. 视觉规范

### 5.1 三种格子

| 状态 | 样式 | 语义 |
|---|---|---|
| 空闲 | `bg-state-ok` 实心 | 现在能用 |
| 占用 | `bg-ink-200` 实心 | 有作业占着 |
| 不可用 | `border border-ink-300` 空心（实施时改了：7px 画不了斜线）| 维护/故障，**不能提交** |

**颜色 + 形状双编码**：色盲用户靠实心/斜线也能分辨，不单靠红绿。

- 尺寸：`7px × 7px`，`gap 2px`，`rounded-[1px]`
- 8 卡一行约 70px；超过 8 张用 `flex-wrap` 折行（`max-w-[120px]`），**不缩小格子**
- 非文本元素的对比度目标是 **3:1**（不是正文的 4.5:1），`state-ok` / `ink-200` 都够

### 5.2 严格使用已注册 token

只用 `bg-state-ok` / `bg-ink-200` / `bg-ink-100` / `border-ink-200`。
**不新造 `bg-slot-*` 之类**——Tailwind 对未注册 token 是**静默无输出**，
构建和 tsc 全过，只是格子没有颜色（`docs/04 §2.12` 记过这个坑）。

改完必须去构建产物里 grep 一次类名，确认规则真的生成了。

### 5.3 交互

- `title` 写全：`gpu10 · A100 · 共 8 张，空闲 5`
- `aria-label` 同上（格子本身没有文本）
- 点任意格子 → `onOpenJobs(node)`（就是现有的「谁在用」）
- 不做 hover 放大（列表里逐行扫视时，放大反而打断节奏）

## 6. 边界与异常

| 情况 | 处理 |
|---|---|
| 节点有 16 卡 | 折行，两排 × 8 |
| 机器有多型号 | 每张型号卡只画自己那型；其它型号的占用不影响本行 |
| `freeMemoryMb === null`（集群没给） | 保持现有 `—`，不影响格子 |
| 核满但卡空（`idleCpus <= 0`，混部常见） | 格子仍是"空闲"，行尾保留「核满」提醒——格子只说卡 |
| 型号名很长 | 卡片头已经有 `title`，格子区不放文字 |

## 8. 测试（`tests/gpu-slots.test.ts`）

| 用例 | 期望 |
|---|---|
| 空闲 8 卡、无作业 | 8 个 `free` |
| 8 卡用了 3 张 | 3 个 `used` + 5 个 `free`（顺序无关，按数量断言） |
| `blocked: true` | 全部 `blocked`，**即使 gpusUsed 是 0** |
| 多型号：A100×4 用了 4，V100×4 用了 0 | 查 A100 → 全 used；查 V100 → 全 free |
| 不存在的型号 | 空数组（不抛） |
| `used > total` | 长度等于 total，全 used（不出现负数） |
| `slotSummary` | total / free 与逐节点相加一致 |

## 9. 风险

| 风险 | 对策 |
|---|---|
| 用状态名判断空闲 | 只允许 `blocked + gpusUsed`，测试里专门有一条"drain 但有 8 张空卡" |
| 新造 token 静默失效 | 只用已注册的 `state-*` / `ink-*`；改完去产物 CSS grep |
| 128 个方块拖慢渲染 | 纯静态节点，无动画；一张卡片最多 16 台 × 8 格，不虚拟化也够 |
| 用户把"格子"当可点击下单 | 点击打开的是「谁在用」，不是下单；hover 文案写清 |
