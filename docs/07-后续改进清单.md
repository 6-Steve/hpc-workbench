# 后续改进清单（2026-11-16）

> 判断标准只有一条：**每天会不会碰到 × 现在有多痛**。
> 好看但用不上的、以及"看起来高级但成本在钱不在代码"的，都放在最后明确不做。

现有功能已覆盖：SSH 连接、SFTP 传输队列、作业提交/监控/生命周期通知、配额、点数、
正反向隧道、终端、命令面板、命令台、三套主题、字体方案、首次向导、SSH 配置导入、跳板机测速。

---

## 一、三个主要改动

### 1. 目录增量同步（传输）★ 详细计划见 `docs/10`

**痛点**：每跑完一轮实验，`results/`、`ckpt/` 动辄几百 MB。现在只有"整个目录重传"或"手动挑文件"；
`fastPut/fastGet` 传一半断了也是从头再来。

**做什么**

- 传输页加「同步这个目录」：递归列远端树 → 按 **大小 + mtime** 双向比对 → 只传差异
- 大文件支持断点续传（SFTP `PUT`/`GET` 带 offset，落盘先写 `.part`）
- 冲突策略沿用现有规则：默认跳过、目录不许 overwrite

**为什么对你值**：复现论文的本质就是"反复生成/拉取一堆文件"。省的不是几分钟，是每次都得记着"哪几个文件是新的"。

**成本**：中。树遍历与比对是纯逻辑（易测）；续传要动 `transfer/`。

**风险**：mtime 精度（SFTP 只到秒）、时钟偏差、符号链接。建议首版**只比大小 + mtime ±2s**，并把"判定为相同但实际不同"的情况显式记进日志。

---

### 2. 诊断包导出 ★ 已单独出详细计划（见 `docs/08`）

**痛点**：出问题时只能截图，可见信息很有限。

**做什么**：诊断页一键生成 `hpc-diagnose-<时间戳>.tar.gz`，内含版本信息、脱敏后的配置、
最近 200 条命令记录、探测结果、错误日志尾部。

**为什么对你值**：把排障从"你描述 → 我猜 → 你再试"变成"你发我 → 我直接看"。

**成本**：低。数据全是现成的，唯一需要认真做的是**脱敏**。

---

### 3. 资源页的卡位矩阵 ★ 详细计划见 `docs/09`

**痛点**：空闲卡现在是表格里的数字，要扫好几行才知道"现在能不能立刻跑"。

**做什么**

- 每台节点一行小方块，一张卡一个格子：空闲 / 占用 / 不可用（`DRAIN`、`DOWN`）三态
- 顶部一行汇总：`现在可用 A100×8 · V100×10`，直接回答"能不能提交"
- 机型和型号混部时按型号分行（本集群一台机器可能有多种卡）

**为什么对你值**：唯一一个**纯视觉就能提升判断速度**的改动。数据已经在 `ResourcesView` 里，不用新增网络请求。

**成本**：中低。

**注意**：`scontrol` 从不返回 `MIXED`——有作业就是 `ALLOCATED` 但仍有空卡。
格子要按 `blocked && free > 0` 推导，不能照搬 state 字段（`docs/03` 已记录这个坑）。

## 二、次一级（值得做但不急）★ 详细方案见 `docs/12`

| 项 | 说明 | 成本 |
|---|---|---|
| **编辑主机表单** | 改个端口还要开 JSON，是现在最后一处"必须懂文件格式"的地方 | 中低 |
| **作业组** | 一次实验几十个 job，现在平铺；分组后能看"这批完成几成" | 中 |
| **托盘常驻** | 挂着隧道/长任务时，关窗不退出（现在 `window-all-closed → quit`） | 低 |

## 三、美化（低成本、当天能看见）★ 详细方案见 `docs/11`

1. **空状态**：文件页/作业页空时是"暂无数据"，改成一句可操作的话 + 一个淡图标
2. **数字对齐**：点数页已是标杆（`text-right tabular-nums`）；只差隧道/传输/资源三处行内指标——见 `docs/11 §B`
3. **状态点统一**：尺寸其实已统一（都是 6px）；真正的问题是**圆点 vs 胶囊两套语言**——见 `docs/11 §C`
4. **卡片间距节奏**：`space-y-4` 与 `mt-4` 混用，长页面上疏密不匀

> 美化类改动都要过 `tests/design-tokens.test.ts` 的硬断言（骨架、字号、语义色对比度），
> 顺手改的时候别引入 `text-ink-400` 这类低对比色。

## 四、明确不做

| 想法 | 为什么不做 |
|---|---|
| 代码签名 / 自动更新 | 成本在**证书和服务器**，不在代码。自用点两次 SmartScreen 就行 |
| 第四套主题 | 三套已够；每加一套都要重新过 172 处对比度检查 |
| 多窗口 / 标签页 | 单人自用，切换器 + Dock 够用，加了是负担 |
| 内置文件编辑器 | 有 VS Code，重造是浪费 |
| 仪表盘首页 | 资源页 + 作业页已覆盖（这是早期就定过的产品决策） |

---

## 五、排序建议

**先 2 → 再 3 → 最后 1**

| 顺序 | 项 | 理由 |
|---|---|---|
| 1 | 诊断包导出 | 一天能做完，且立刻改善后续所有排障效率 |
| 2 | 卡位矩阵 | "能看见成果"的那种，适合当调剂 |
| 3 | 目录增量同步 | 工作量最大，等日常摩擦清掉再动 |
